ЗАДАЧА: DUNE 2000 PS1 NATIVE — УБРАТЬ PS1 EMULATION/FALLBACK И ДОБАВИТЬ PC INPUT

Текущее состояние
=================

Уже существует рабочий proof-of-concept Dune 2000 PS1 SLUS-00973 под Windows x64.

Подтверждено:

- standalone Windows x64 executable;
- оригинальный boot;
- intro FMV;
- главное меню;
- выбор Atreides;
- briefing;
- запуск A1;
- оригинальная игровая сцена;
- исходный MIPS-код в значительной части AOT/recompiled в host x64.

Но текущая архитектура всё ещё hybrid:

1. большая часть игрового MIPS-кода статически рекомпилирована;
2. неподдержанные/непокрытые участки могут уходить в fallback MIPS interpreter;
3. GPU/SPU/CD/BIOS/timers/pad работают через PS1 compatibility runtime;
4. raw BIN всё ещё используется как runtime CD source.

Это был правильный промежуточный milestone.

Теперь требуется сделать следующий архитектурный переход:

Dune 2000 PS1
       ↓
recovered/recompiled gameplay code
       ↓
native host abstraction
       ↓
Windows x64

Без MIPS interpreter.

Без BIOS emulation.

Без runtime-модели PS1 CPU/hardware registers.

Без необходимости эмулировать PlayStation как устройство.

Это должен стать настоящий source/recomp port.

Пока не делать:

- enhanced AI;

- Emperor;

- новые юниты;
- batch production;

Сначала получить чистый native baseline.

Текущий AI-001 остаётся открытым и НЕ должен маскироваться gameplay-патчами.


============================================================
2. УБРАТЬ MIPS INTERPRETER ПОЛНОСТЬЮ
============================================================

Это главный приоритет.

Сейчас существует residual interpreter fallback.

Необходимо добиться:

interp_instruction_count = 0
interp_fallback_count = 0
interp_unsupported_count = 0

для всего проверенного игрового пути.

Не допускается ситуация:

"обычно native, но редкие ветки выполняются интерпретатором".

Нужно:

1. инвентаризировать ВСЕ адреса/continuations, уходящие в interpreter;
2. классифицировать их:
   - missed function;
   - indirect jump;
   - jump table;
   - overlay;
   - BIOS vector;
   - callback;
   - interrupt continuation;
   - dynamically resolved address;
3. добавить их в AOT/static recomp pipeline;
4. восстановить корректные control-flow edges;
5. исключить interpreter из release binary.

В debug build допускается assertion:

if (execution_attempts_interpreter)
    fatal("Unexpected MIPS fallback");

Но самого MIPS interpreter в release build быть не должно.


============================================================
3. OVERLAYS
============================================================

Отдельно разобрать DUNE overlay system.

Текущий NATIVE-001 указывает, что часть проблемы связана с:

- overlay continuations;
- BIOS RAM vectors.

Не хардкодить отдельные адреса хаотично.

Нужно построить системный overlay loader/recompiler:

overlay image
    ↓
known PS1 load address
    ↓
static function map
    ↓
native function table

Если overlay содержится на CD:

импортировать его при asset import/build stage.

В runtime overlay load должен означать:

активировать соответствующий native module/function table,

а НЕ:

загрузить MIPS blob и начать его интерпретировать.


============================================================
4. УБРАТЬ BIOS EMULATION
============================================================

Определить все BIOS calls, которые реально использует Dune 2000.

Для каждого заменить его на host/native implementation.

Категории:

- memory;
- events;
- threads/callbacks;
- controller;
- CD;
- file I/O;
- timers;
- memory card;
- system utility calls.

Сделать таблицу:

PS1 BIOS call
→ caller(s)
→ semantics
→ native replacement

Например:

PS1 PAD BIOS/API
→ InputBackend

PS1 CD API
→ FileSystemBackend

PS1 memory-card
→ SaveBackend

После этого runtime НЕ должен загружать retail BIOS или OpenBIOS.


============================================================
5. GPU: НЕ ЭМУЛИРОВАТЬ PS1 GPU, А ПЕРЕВОДИТЬ DRAW COMMANDS
============================================================

Оригинальный game code может продолжать формировать структуры вроде:

POLY_FT4
POLY_F4
SPRT
TILE
DR_MODE
OT

Это нормально.

Но host backend не должен моделировать:

- PS1 GPU registers;
- GP0/GP1 command FIFO;
- DMA hardware;
- VRAM как эмулируемое устройство;
- GPU timing на уровне железа,

если это не необходимо для семантики игры.

Сделать translation layer:

original game render primitives
          ↓
DuneRenderCommand
          ↓
native renderer
          ↓
SDL/OpenGL

Например:

POLY_FT4
→ textured quad

SPRT
→ sprite

TILE
→ solid rectangle

DrawOTag
→ обход ordering table и генерация host draw calls

Сохранить:

- draw order;
- blending semantics;
- palette/CLUT semantics;
- texture coordinates;
- transparency;
- dithering, если она влияет на внешний вид;
- original viewport.

На первом этапе:

384x240 / оригинальная логическая система координат.

Не делать пока HD graphics.


============================================================
6. TEXTURE / VRAM ABSTRACTION
============================================================

Если игра использует PS1 VRAM coordinates как IDs ресурсов, допустимо сохранить
логическую модель.

Но реализовать её как software resource atlas / texture manager.

То есть:

PS1 texture page + CLUT
→ NativeTextureHandle

а не полноценная эмуляция GPU VRAM.

Если для parity проще сначала сохранить 1024x512 software VRAM buffer,
это допустимо как transitional representation,

НО:

это должно быть обычной структурой renderer backend,
а не PS1 GPU emulator с регистрами и command processor.

Backend:

Главное:

железо SPU больше не эмулируется.

============================================================
9. TIMERS / VBLANK / GAME LOOP
============================================================

Это критически важно из-за текущего AI-001.

Не использовать:

"примерно 60 Hz, вроде похоже".

Нужно восстановить реальную семантику оригинала.

Определить:

- NTSC VBlank rate;
- game logic tick;
- animation tick;
- AI update cadence;
- interrupt callbacks;
- timer progression;
- frame skipping;
- number of original CPU cycles, если game logic на это реально полагается.

Сделать native scheduler.

Например:

HostFrame()
{
    PollInput();

    while (logicAccumulator >= GameTick)
        OriginalGameTick();

    Render();
}

Но конкретную модель взять из наблюдаемого поведения оригинала.

AI-001 считать блокирующим regression-test.

Не "чинить AI".

Исправить timing/runtime так, чтобы исходный AI снова вёл себя правильно.


============================================================
10. CONTROL FLOW / FUNCTION POINTERS
============================================================

Особое внимание:

- function pointers;
- callbacks;
- jump tables;
- event callbacks;
- interrupt callbacks;
- overlay entry points.

Нельзя оставлять:

native code
→ fake PS1 PC address
→ interpreter dispatch.

Нужна таблица:

PS1 address → native function pointer.

Например:

NativeFn ResolvePsxFunction(uint32_t psxAddress);

И все известные execution paths должны разрешаться в native host function.

12. МЫШЬ — ПРЯМОЕ УПРАВЛЕНИЕ КУРСОРОМ
============================================================

Главное изменение управления.

Сейчас оригинал двигает cursor через PS1 controller.

На PC мышь должна управлять игровым курсором НАПРЯМУЮ.

Не делать:

mouse delta
→ virtual D-pad
→ постепенное движение курсора.

Нужно:

host mouse position
→ game cursor position.

Учитывать:

- window size;
- integer scaling;
- letterboxing;
- fullscreen;
- viewport transform.

Например:

window mouse coordinates
        ↓
logical game coordinates
        ↓
original cursor X/Y

Ограничить cursor original viewport bounds.
