# Состояние native-порта — 2026-09-30

**Core-native milestone НЕ достигнут.** Готов следующий исследовательский шаг:
прямой PC input и сборка, из которой удалён MIPS evaluator и которая прекращает
работу при недостаточном статическом покрытии. Это два разных исполняемых файла.

## Запуск

- `RunPCInput.cmd` → `build/pc/Dune2000Native.exe`: рабочий исследовательский
  вариант с новым вводом, всё ещё hybrid. Обычный запуск отключает debug server.
- `RunDune.cmd` → сохранённый предыдущий прототип с исходным virtual-pad вводом.
- `RunRelease.cmd` → `build/strict/Dune2000Native.exe`: строгая диагностика,
  сейчас завершается с кодом 86 до главного меню. Это не игровой release.

`scripts/build.ps1 -Step build -PCInput` воспроизводит PC build;
`scripts/build.ps1 -Step build -Release` всегда включает strict AOT.
Прежний `build/release` относится к старому hybrid-прототипу и больше не является
целевым результатом команды Release.

## Выполненные изменения

Boot раньше имел только 59 найденных входов. Теперь используется 108 статически
обнаруженных функций/callbacks из анализа исходного SLUS. Overlay exports
строятся системно: адресные слова из оригинального файла должны указывать на
статически декодированную функцию/блок того же модуля. Для функций с внутренними
входами добавляются остальные начала CFG-блоков. Никакой RAM dump не служит
исходным кодом для генерации.

Два исходных модуля D2KF/DUNE дают 63 247 guarded entry/continuation variants.
Это **не количество функций** и не доказательство полного покрытия. Извлечение
и аудит исходных байтов проходят; `full_static_coverage_proven` остаётся false.
Метаданные: `research/static-transfer-exports.json`.

`tools/prepare_runtime.py` воспроизводимо создаёт адаптированные translation
units из закреплённого upstream, не редактируя `third_party`. В strict сборке
нет исходного `dirty_ram_interp.c`, `psx_interpreter.c` или opcode evaluator.
`interp_step/run` и попытка неизвестного dispatch вызывают fatal. Сохраняются
диагностический JSON и локальный RAM snapshot, затем процесс завершается с 86.
Это реальное удаление evaluator, но ещё не удаление CPU/hardware runtime.

Все адреса в сохранённой fallback-телеметрии собраны в
`research/fallback-inventory.json`. Исторический формат не хранит overlay ID:
совпадающие адреса D2KF/DUNE помечены неоднозначными. Нельзя выдавать этот список
за все возможные пути игры. `docs/BIOS_CALLS.md` перечисляет 74 статических BIOS
thunks и их прямых callers; host replacements для них ещё не подключены.

В последнем длительном headless прогоне PC build до A1 зарегистрировано
204 603 391 interpreted instructions; это не нулевой fallback и не native-only
путь. Отсчёты нельзя напрямую сравнивать с более короткими старыми сессиями.
Текущий cumulative inventory содержит 555 адресов из всех сохранённых прогонов.

## Точный строгий отказ

Последовательность проверок: `800141BC` (boot callback), `80030A80`
(внутренний переход D2KF), `80030D54` (выход из восстановленной таблицы), затем
`8004545C`. Последний отличается по природе от предыдущих.

В D2KF `80045454` вызывает B0:57 GetB0Table; возврат — `8004545C`.
В момент отказа оригинальные слова по `8004545C`, `80045464`, `80045468`
заменены на NOP, безусловную ветку и NOP. В статически переведённом OpenBIOS
находятся соответствующие routines `BFC080AC/BFC080D0`, записывающие ветку
в вызывающий SDK. Guard диапазона `8004543C..800454AC` поэтому не совпадает.
Отключать guard или исполнять исходную функцию при изменённых байтах нельзя.

Следующее изменение должно восстановить семантику этой platform boundary
либо доказать и статически перевести её варианты. Полная цель требует заменить
BIOS APIs host-реализациями, а не называть новый BIOS-вариант удалением BIOS.

Смотри `INPUT.md`, `PARITY.md`, `REMAINING_PS1_DEPENDENCIES.md` и свежие
`research/validation.json`, `research/native-release-gate-*.json`.

эталонного сравнения AI, save/load и audio/FMV parity нет. Новые дома, юниты,
улучшения AI и баланс в этот проект не добавлялись.
